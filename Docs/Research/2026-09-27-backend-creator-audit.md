Scope: read-only source audit of the backend at commit `45efbdc` (the latest commit reverts `creator-stats` because it duplicated `creator_insights`). ## Existing product boundary

The correct extension point is `creator_insights`, not a second creator-stats service. It already aggregates views, impressions, dwell, watch samples, reactions, favorites, saves, shares and follows. The current creator permission requires a published submission; analytics is a plan feature but its default and seeded plans allow it for free.

- `GET /api/v1/creators/me/insights/?period=week|month|all`: owner-scoped insights; authenticated + `IsCreator` + `HasFeature('creator_analytics')`. [View](/Users/narekmeloyan/PycharmProjects/JokesForProject/creator_insights/views.py:21), [permission](/Users/narekmeloyan/PycharmProjects/JokesForProject/creator_insights/permissions.py:4).
- `GET /api/v1/creators/{id}/profile/`: public identity, visible published count, current follower count, following state, paginated content (10/page). Applies viewer content-tier rules and symmetric blocks. [Profile view](/Users/narekmeloyan/PycharmProjects/JokesForProject/creator_insights/views.py:48).
- `GET /api/v1/creators/{id}/tips/summary/`: public count and total cents of succeeded tips; separate from insights. [Tip summary](/Users/narekmeloyan/PycharmProjects/JokesForProject/billing/views.py:261).
- Creator drafts/submissions already have list, create, edit and submit endpoints. Published content is read-only through the public joke viewset; a submission can only be edited in draft/rejected status. [Routes](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/urls.py:34), [edit restrictions](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:1842).

There are no creator-insights database tables, scheduled aggregation, cache, or stored dashboard counters. All aggregation is on request. Top-joke counts deliberately use correlated subqueries to avoid a view×reaction×save×share join explosion. The top-joke section has a four-query regression test. [Service](/Users/narekmeloyan/PycharmProjects/JokesForProject/creator_insights/services.py:1), [subqueries](/Users/narekmeloyan/PycharmProjects/JokesForProject/creator_insights/services.py:215), [test](/Users/narekmeloyan/PycharmProjects/JokesForProject/creator_insights/tests/test_services.py:858).

## What the metrics actually mean

| API metric | Current definition and limitation |
| --- | --- |
| `published_jokes` | Count of currently non-removed attributed jokes, independent of selected period. Attribution uses `Joke.creator`, with a published-submission fallback only where creator is null. |
| `views` | Number of authenticated `JokeView` rows in the window. Unlocked detail GETs create rows with a 60-second user/joke debounce. Not unique viewers, not necessarily a reveal or a full read. |
| `reach` | Distinct users represented in those view rows. |
| `impressions` | `JokeImpression` rows: intended to be at most one authenticated user/joke/day. This counts daily exposures, not every card display. |
| `unique_reach` | Distinct users in impression rows, a different population from `reach`. |
| `open_rate` | `min(view_rows / impression_rows, 1)`, null without impressions. It is not a matched impression-to-open conversion rate. Reopens inflate its numerator and populations can differ. |
| `payoff_rate` | Fraction of view rows whose mutable `revealed_punchline` flag is true. Reveal ingestion updates the latest historical view for that user/joke, without a same-day/session constraint, or creates a view if none exists. |
| `avg_read_seconds` | Mean dwell sample milliseconds / 1000. Samples may be repeated and are not deduplicated into sessions. |
| `read_rate` | Fraction of dwell samples at least 4 seconds long. Not fraction of impressions or views that were read. |
| `completion_rate` | Fraction of dwell rows with known scroll percentage that reached 90%. Null when no scroll samples exist; the other dwell samples are excluded from its denominator. |
| `reactions`, `favorites`, `saves` | Currently existing reaction/favorite/save rows created within the window. These are mutable relationships, not immutable action events. Removing an edge erases it from historical counts; switching reaction type changes its breakdown while retaining original `created_at`. A save is unique per user/joke/collection, so saves can exceed unique saving readers. |
| `shares` | Share endpoint event rows, including anonymous shares. A share intent is recorded; successful delivery, click-through and recipient conversion are not measured. |
| `peak_read_hour` | Hour with most view rows, using Django's current timezone (default UTC), not a reader-local optimum. |
| `daily_reach_28d` | A 28-element count of view rows per day, despite the “reach” name. It reuses the period-filtered view queryset; selecting `week` zeroes out the preceding 21 positions. |
| `followers` | Current `Follow` rows, independent of period. |
| `follower_growth_28d` | Current surviving follows grouped by creation day over 28 days, independent of period. Unfollow deletes the edge, so this is neither historical follows gained nor net growth. |
| `top_jokes` | At most 10 jokes ranked by view count. Includes text, views, impressions, reactions, saves, shares, payoff/read metrics, and watch metrics. No pagination, filters or per-joke drilldown. |
| `avg_watch_seconds`, `watch_completion_rate` | Top-joke-only metrics for jokes currently carrying audio/video media. Mean watch sample and fraction of samples with known watch percentage reaching 90%. No overall watch total or retention curve. |
| `audience.top_themes/categories/formats` | View counts grouped by the creator's currently assigned joke tags/format. This describes viewed content, not a demographic, cross-creator taste profile, or retention cohort. A multi-tag joke contributes to multiple buckets. Editing tags reclassifies historical views. |

`week` starts six dates before today: seven inclusive UTC dates. `month` starts 29 dates before today: 30 inclusive dates, despite the comment saying “29-day window.” `all` removes the lower bound. Unknown values silently become `month`. There is no explicit end bound, date range, comparison period or timezone parameter. Publication count, follower count and follower sparkline are not governed by the main period. ## Collection, privacy and reliability gaps

`POST /api/v1/telemetry/events` requires authentication and accepts `impression`, `reveal`, `dwell` and `watch`. It caps each batch at 50, clamps dwell/watch to 500–600,000 ms, clamps percentage to 0–100, and silently skips bad events. The `accepted` number counts handled events, including already-existing impressions/reveals; it is not inserted-row count. [Ingest](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:3942).

The following matter before charging for interpretation of these numbers:

1. **Consent populations are not reconciled.** `UserProfile.share_analytics` defaults false and can be changed in preferences, but the backend neither checks it when ingesting telemetry nor filters aggregates by it. `JokeView` is an operational activity record written for authenticated detail reads without this check. If a client only sends telemetry after consent, views and impressions come from different populations; the current open rate combines them anyway. A trustworthy explorer must explicitly distinguish operational activity from consenting audience telemetry and define every denominator. The backend alone cannot establish which clients currently enforce consent. [Flag](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/models.py:535), [preference update](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:2552), [ingest](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:3994).
2. **Anonymous viewing is unmeasured in creator analytics.** All four view/impression/dwell/watch models require a user. Anonymous consumption is currently a signed paywall cookie, not creator telemetry. Share events are the exception. Free viewing will make this coverage limit particularly visible. Avoid presenting authenticated reach as total audience.
3. **No stable event/session identity.** There is no event UUID, client platform, event schema version, occurrence timestamp distinct from receipt time, playback session, asset ID or retry idempotency key. Dwell/watch retries inflate sample counts; offline submissions are attributed to receipt time. The model allows source strings while ingestion only truncates to 16 characters, so source taxonomy is not normalized consistently.
4. **Impression deduplication lacks a database uniqueness constraint.** `get_or_create(user, joke, created_date)` has only ordinary indexes, so concurrent requests can still produce duplicate rows. A future constraint needs a duplicate-cleanup migration first. [Model](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/models.py:1129), [migration](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/migrations/0028_jokeimpression.py:25).
5. **Ingest checks existence, not viewer eligibility.** It checks `Joke.objects.filter(pk=...).exists()`, which excludes removed jokes, but does not enforce mature-tier eligibility, symmetric blocking, media kind for watch, or exclude creator self-events. A caller can submit fabricated telemetry for a known eligible database ID. Silently catching every exception also hides ingestion/storage faults from the caller. [Validation](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:4015).
6. **Mutable edges cannot answer historical growth honestly.** Reactions/saves/favorites/follows need either clear “currently retained” labeling or independent action history before they can power churn, acquisition, conversion or net-growth charts. Impression/view data can support authenticated first-time/returning-reader calculations, but these cohorts are not implemented and would still need a declared lookback and coverage policy.
7. **Privacy support is incomplete for new telemetry.** Insights expose aggregates, not reader identifiers, and tests cover creator isolation and no email/username leaks. There is no minimum sample suppression or demographic cohort logic. User-linked telemetry cascades on account deletion. The data export includes up to 5,000 views, reactions and shares, but does not include impression/dwell/watch rows. No telemetry retention job/window is implemented. [Isolation tests](/Users/narekmeloyan/PycharmProjects/JokesForProject/creator_insights/tests/test_compliance.py:113), [export](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:3165).

Current suggestions are three heuristics: busiest hour, tone with highest reactions-per-view, and days since latest published submission's `updated_at`. There is no minimum sample size, confidence interval, experiment, baseline comparison or causal evidence. The claim “Creators who post 3–5× per week grow their audience fastest” is hardcoded, not derived from collected data. A creator with directly attributed jokes but no published submission can have content yet fail `IsCreator`; consistency also only looks at submissions. [Suggestions](/Users/narekmeloyan/PycharmProjects/JokesForProject/creator_insights/services.py:386).

## Metadata and creator content model

`Joke` already has full text, setup, punchline, dialogue lines, format, age rating, language, source attribution, creator FK, tones/categories, context tags/themes, culture tags, content tier, removal state, timestamps, search vector and generated share image. `JokeSubmission` mirrors most creative metadata and stores owner, draft/pending/published/rejected status, rejection reason and a one-to-one published joke. [Joke fields](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/models.py:101), [submission fields](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/models.py:624).

Publishing in admin copies creative metadata and media, stamps `creator=submission.user`, derives mature tier from age rating, links the published joke and marks the submission published. Creator attribution is nullable for legacy/curated content and uses `SET_NULL` when the account is erased; submission ownership uses `CASCADE`. Existing migrations `0024` and `0025` added/backfilled the creator FK. The reverse of `0025` clears all creator attribution, so do not roll this migration back as a migration strategy. [Publish](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/admin.py:327), [backfill](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/migrations/0025_backfill_joke_creator.py:4).

`MediaAsset` records owner, image/video/audio kind, files/poster, dimensions, duration, GIF flag, screening result, perceptual hash, quarantine date. Ordered join tables attach assets to submissions and jokes. Formats and validation rules already cover text, image, video and audio. This is enough to derive word count/read-time buckets and media duration without collecting new audience data. [Assets](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/models.py:1411), [format rules](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/submission_rules.py:9).

Missing creator SaaS metadata includes explicit publication timestamp/history, content revision/version, caption/transcript, accessibility alt text, rights/license declaration, structured humor mechanism, creative intent/hypothesis, series/campaign, experiment variant, and tag provenance/confidence. These should be introduced only for a defined workflow, mirrored through draft→publish, and versioned where they change historical interpretation. There is currently no publish scheduler, collaborator/team ownership, or creator-facing published-content revision flow.

## Free-viewing dependency map

The reading paywall and safety tiers are independent mechanisms:

- The paywall limits free authenticated readers to 10 distinct joke IDs/day via the operational `JokeView` table. Anonymous readers have a separate hardcoded 10/day signed cookie. Merely setting the free plan JSON limit to null does **not** remove the anonymous cap. `JokeSerializer` strips text, punchline and lines and withholds media URLs when locked. [Paywall](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/paywall.py:116), [stripping](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/serializers.py:269).
- Paywall context appears across list/detail, discovery/random, collections, saved/favorite/recent lists, mystery box and packs. The daily editorial path is intentionally exempt. Preserve operational view recording when retiring the commercial cap: streaks, recent reads, preferences and recommendation exclusion depend on it. [Context injection](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:171), [view model dependencies](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/models.py:1011).
- Reader plan limits also include Mystery Box rolls and daily history length. Mystery Box code assumes a finite integer and subtracts/compares it, so a null/unlimited setting needs implementation work rather than only a plan edit. Daily history already supports null. [Mystery](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:3388), [history](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/views.py:1394).
- `submissions_per_day`, `daily_jokes_per_day`, `daily_joke_preview` and `mature_content_addon` are declared plan keys but have no enforcing feature/quota call sites in application code. Do not assume the seeded catalog describes implemented restrictions. [Registry](/Users/narekmeloyan/PycharmProjects/JokesForProject/billing/entitlements.py:18).
- Safety tiers must remain: tier 1 by default; tier 2 only for authenticated adults who opted in; tier 3 never served publicly. Global takedown filtering and symmetric blocking are separate from billing. [Tier policy](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/serving.py:1), [manager](/Users/narekmeloyan/PycharmProjects/JokesForProject/jokes/managers.py:6).

Billing has editable Plan JSON capabilities, one subscription per user, Stripe Checkout/Portal/webhook synchronization and a denormalized `profile.is_premium`. Seeded prices explicitly say PLACEHOLDER. Existing tips are receipts and public totals, not a creator payout ledger; Stripe Connect payouts are explicitly absent. Main payment audit is owned by the parent task. [Plan/subscription](/Users/narekmeloyan/PycharmProjects/JokesForProject/billing/models.py:5), [seed catalog](/Users/narekmeloyan/PycharmProjects/JokesForProject/billing/migrations/0002_seed_plans.py:1), [tip limitation](/Users/narekmeloyan/PycharmProjects/JokesForProject/billing/models.py:98).

## Bounded implementation recommendation

First implement **permanently free consumption with preserved safety controls**: make anonymous/authenticated content reads unlimited, retire the cookie ledger/reader upsell behavior compatibly, make Mystery Box and history independent of paid plans, and migrate only the relevant plan JSON keys without replacing Stripe IDs or subscription records. Keep ordinary abuse throttling and operational `JokeView` events. Test all formats and public/private reader paths with more than 10 prior reads, stale capped plan rows, anonymous cookies, mystery/history boundaries, mature-tier exclusion, blocked creators and takedowns.

Then add a **creator content explorer inside `creator_insights`**, reusing attribution and scalar subqueries: a paginated owner-only content list with validated sort/filter/date window, metadata, meaningful metric labels, sample sizes and collection coverage. Keep the existing response compatible. Resolve consent/cohort semantics and ingestion identity before adding a conversion rate or asserting audience growth; retain null/insufficient-data states instead of manufacturing an interpretation. New/returning readers, retention cohorts, historical follower growth and demographic cohorts are separate features, not existing data that a UI can simply display. Do not recreate the reverted creator-stats endpoint.

Potential first analytics migration: deduplicate existing impressions and add the user/joke/date unique constraint, plus stable retry identity for new telemetry. Migration sequencing matters because historical samples lack these identities; mark that provenance instead of fabricating it. Advanced paid creator entitlements should describe capabilities that actually exist; avoid silently charging for or removing the already-free basic insight endpoint.
