## Measurement findings and priorities

### Existing web transport

`src/lib/telemetry.ts` accepts impression/reveal/dwell/watch events; gates enqueue and flush on real API mode, access token, authenticated account, adult DOB, and local analytics consent; buffers 10 events, caps batches at 50; uses authenticated `fetch(...keepalive: true)`; and flushes on visibility hidden/pagehide. It intentionally avoids the previous credential-less beacon path. Impression/reveal deduplication is module-lifetime `(event type, joke, source)`; dwell/watch are append-only samples. [Gate and state](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/lib/telemetry.ts:62), [transport and flush](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/lib/telemetry.ts:95), [enqueue](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/lib/telemetry.ts:160).

The audit found the following source-level risks. Passing current tests does not rule them out; the tests primarily isolate hooks from transport.

- **P1: account lifecycle attribution.** Queued events have no account owner; `send()` obtains the current token. Logout clears auth/React Query but does not clear queue or dedup state. A person can queue events as A, log out and into B before flush, then send A's queued events with B's token; B also inherits A's seen-set suppression. Bind a telemetry session to account identity and clear/drop on auth transitions. [Event shape](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/lib/telemetry.ts:30), [send](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/lib/telemetry.ts:95), [logout](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/auth/store.ts:45), [query cleanup](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/auth/api.ts:144).
- **P1: consent source mismatch.** Telemetry checks local cookie consent only. Settings offers `privacy.shareAnalytics` and persists it to the API, but this preference is not read by the client gate. Share recording has authentication checks but no age or consent gate. Backend policy must settle the distinction between operational actions and optional analytics; use one documented policy, rather than two apparent opt-outs with different effects. Consent rejection does not disable an already initialized Firebase instance. [Settings](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/pages/SettingsPage.tsx:271), [gate](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/lib/telemetry.ts:73), [share](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/telemetry/recordShare.ts:13), [consent rejection](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/consent/useConsent.ts:29).
- **P1: dwell lifecycle delivery.** `useDwell` only pauses on hidden, and its pagehide listener enqueues without explicitly flushing. If the module flush listener was registered before this card mounted, it runs before the new dwell sample is queued; the last sample can be lost on unload. `useWatchTracking` already documents/fixes the analogous ordering problem via an explicit final flush. Flush accumulated dwell before transport on hidden/pagehide and test listener ordering with the real buffer. [Dwell lifecycle](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/telemetry/useDwell.ts:123), [watch precedent](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/telemetry/useWatchTracking.ts:79).
- **P1: watch-time semantics.** The watch hook sends cumulative maximum media `currentTime`, not elapsed played time, at each pause/end. A pause at 5 seconds then 10 seconds produces samples 5000 and 10000; seeking jumps the value and replay below the previous maximum contributes nothing. Match the backend's sample/aggregation contract before selling this as average watch time or retention. Track actual played intervals/deltas or define a stable play-session update contract. [Watch calculation](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/telemetry/useWatchTracking.ts:52).
- **P2: impression quality and consent transition.** The hook's one-second timer does not check document visibility; it marks itself fired before the telemetry gate accepts the event, so a card first viewed before consent will not retry on consent acceptance without remounting. [Impression timer](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/telemetry/useImpression.ts:32).
- **P2: tall stories and teaser dwell.** Both impression and dwell require at least half of the element to be visible. A story taller than twice the viewport cannot meet that threshold. Dwell runs on the whole card, even when locked or unrevealed, so current samples may measure reading a teaser rather than the payoff. Declare metric semantics and observe an appropriate reading region. [Dwell visibility](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/telemetry/useDwell.ts:138), [card wiring](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/components/FlowJokeCard.tsx:100).
- **P2: delivery and share fidelity.** Transport drains before sending, ignores HTTP status, and has no retry or stable event identifier. This is best-effort coverage, not lossless analytics. Clipboard share is recorded even when clipboard writing fails or is unavailable; count it as an attempted share unless recorded after success. [Transport](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/lib/telemetry.ts:115), [share handler](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/components/FlowJokeCard.tsx:132).
- **P1 product measurement gap:** creator workflow events (`creator_hub_viewed`, `draft_created`, `submit_succeeded`, etc.) only log in development; production tracking is a no-op. No measured creator activation/recommendation-adoption funnel is available through that module. [Creator analytics placeholder](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/features/create/analytics.ts:8).

## Data and entitlement mismatches to settle

- Web advertises `creator_analytics` in billing but the insights route/page does not consult it; every 403 is rendered as “Insights unlock when you publish.” If the backend adds a paid restriction, return distinguishable error codes and separate unpublished, insufficient-data, and paid-feature states. Preserve a useful free creator baseline. [403 handling](/Users/narekmeloyan/WebstormProjects/jokes-for-frontend/src/pages/CreatorInsightsPage.tsx:731).
- iOS swallows insights failures with `try?`; if submissions succeed, a paid/transport/decoding failure can silently remove the analytics section. Its model requires `impressions` even though the web type omits that field. Use contract fixtures from the backend and explicit state handling before extending Studio. [Model](/Users/narekmeloyan/XcodeProjects/JokesFor/JokesFor/Models/Creator.swift:14), [load](/Users/narekmeloyan/XcodeProjects/JokesFor/JokesFor/Features/Studio/StudioView.swift:75).
- Web calls `views` “Views”; iOS calls the same field “Reads.” Web distinguishes read-through separately. Align definitions and show observation coverage; current web optional telemetry covers signed-in consenting adults, while iOS does not submit that telemetry. These are not all-viewer population measurements.
- Suggestions and peak hour lack client-side confidence, support counts, coverage dates, or timezone explanation. Existing suggestions can be reused, but should not be presented as proven optimization or personalized certainty without supporting data.

## Smallest useful creator slice

Keep `/create/insights`, its adapter, and existing backend `creator_insights`. Add an evidence panel that explains the period, metric definitions, available sample size/coverage, and insufficient-data state. Make the existing growth suggestion actionable with a bounded “Try this in a new draft” path using the existing editor; do not invent demographic claims or generate a second recommendation engine. Distinguish publishing eligibility from a future paid toolkit entitlement. Add real consent-aware events for insights viewed, suggestion action taken, draft created, and successful submission so the activation path can be evaluated.

Sequence: (1) make viewing/mystery/history free across the backend and web, maintaining old-client compatibility; (2) repair event account/consent/lifecycle semantics; (3) add the evidence/action layer on existing insights; (4) extend native Studio and native collection after the shared contract stabilizes. Price research and package decisions are separate inputs, not assumptions of this slice.
