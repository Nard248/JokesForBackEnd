# MVP 0.2 Slice 2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Steps use `- [ ]`.

**Goal:** Replace submission-join creator attribution with a real, safely-migrated Joke.creator FK; ship a social follow engine (new follows app) with follow/unfollow/status/list endpoints; expose a public, tier-filtered creator profile page (backend + frontend with Follow button via USE_MOCKS adapter); and wire follower count + 28-day follower-growth into creator_insights — all demoable, TDD, scoped.

**Architecture:** Backend Django 5.2 + DRF, single Cloud Run app, Neon Postgres, no workers/cron — all counts computed on-read via aggregates. Joke.creator added nullable+indexed (non-blocking ADD COLUMN) with a SEPARATE data migration backfilling from JokeSubmission.user; publish path (jokes/admin.py approve_and_publish) stamps the FK; creator_insights.services.resolve_creator_jokes swaps to the FK with an OR-fallback to the old submission join for null-creator rows (zero regression). New `follows` app owns the Follow(follower,creator) edge (unique_together, indexed on creator+created_at and follower+created_at) plus a pure-function service layer and DRF endpoints under /api/v1/follows/ and /api/v1/users/me/following/. Public creator profile lives in creator_insights (AllowAny) and re-applies jokes/serving.allowed_tiers — the explicit inverse of owner-scoped insights — importing follows.services for counts/is_following. creator_insights.services + serializer extended with followers + follower_growth_28d. Frontend mirrors the existing creator-insights pattern: new src/features/follows module (react-query hooks + FollowButton), src/pages/CreatorProfilePage, public route /creators/:creatorId, USE_MOCKS-aware adapter (followsAdapter + creatorProfileAdapter), mock fixtures + stateful mockFollowsApi. Backend tests via Django runner on local Postgres (--keepdb); frontend vitest.
